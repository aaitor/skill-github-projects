# Contributing

Use [Issues](https://github.com/aaitor/skill-github-projects/issues) for bugs and proposals. Fork, make a focused change, and open a pull request describing the problem, behavior, and validation.

Keep instructions generic: use `<OWNER>` / `<NUMBER>` placeholders, and fictional `octo-org` examples. Resolve field and option IDs dynamically. Preserve the status model, label filtering, and human approval boundary. Illustrative IDs in the walkthrough are examples, never reusable credentials or live identifiers.

Install `requirements-dev.txt` in a virtual environment and run `python3 scripts/check.py`. CI checks documentation and packaging without GitHub credentials, board operations, or model calls. Live workflows require your own authorized test board; disclose what you verified.

Do not include tokens, private board snapshots, or private issue text. Contributions use the existing MIT license. Follow [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) and report vulnerabilities through [SECURITY.md](SECURITY.md).
